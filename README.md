# Список покупок по блюду

Небольшое приложение на Streamlit: пишешь, что хочешь приготовить, выбираешь количество человек и формат ответа — и получаешь список покупок. Список составляет нейросеть (GigaChat API), запросы идут через официальный SDK `gigachat`.

Сценарий внутри простой: интерфейс → обработчик → вывод. Весь код вызова модели и обработки ошибок вынесен в отдельный модуль `llm.py`, чтобы в UI не было ни одного HTTP-вызова.

## Состав проекта

```
shopping_list_app/
├── streamlit_app.py   # интерфейс (ввод, валидация, вывод)
├── llm.py             # обработчик: промпт, вызов GigaChat, карта ошибок
├── requirements.txt
├── .env.example       # пример переменных окружения
└── .gitignore
```

## Требования

- Python 3.10+
- Учётные данные GigaChat API (Client ID и Secret)

## Установка и запуск

```bash
python -m venv venv
venv\Scripts\activate      # Windows
source venv/bin/activate   # Linux/macOS

pip install -r requirements.txt

copy .env.example .env     # Windows
cp .env.example .env       # Linux/macOS
```

В файл `.env` впишите свои Client ID и Client Secret из кабинета GigaChat и при желании модель:

```
GIGACHAT_CLIENT_ID=ваш_client_id
GIGACHAT_SECRET=ваш_secret
GIGACHAT_MODEL=GigaChat-3-Pro
```

Запуск:

```bash
streamlit run streamlit_app.py
```

Интерфейс откроется на http://localhost:8501.

Замечание по секретам: ключи читаются только из переменных окружения, в коде их нет, а сам `.env` в git не попадает (есть в `.gitignore`). SDK принимает авторизационный ключ в формате base64 — в `llm.py` он собирается автоматически из Client ID и Secret, поэтому дополнительно ничего кодировать не надо.

## Сценарии проверки

| Что вводим | Ожидание |
|---|---|
| Обычный текст, например «Борщ», 2 человека, «Список + шаги» | Список продуктов (по строке на продукт) + шаги приготовления (5–8 пунктов) |
| Пустое поле или одни пробелы | Сообщение «Напишите, что хотите приготовить.», запрос к API не выполняется |
| Текст длиннее 1000 символов | Сообщение «Слишком длинный текст — сократите или разбейте на части.», запрос к API не выполняется |

## Как повторить хотя бы одну ошибку API

1. В `.env` испортить `GIGACHAT_CLIENT_ID` (например, стереть пару символов), перезапустить приложение.
2. Нажать «Сгенерировать список покупок» с любым блюдом.
3. Ожидание: в интерфейсе появится сообщение **«Не настроен доступ к сервису.»** — без traceback и без утечки ключа.

Ещё можно отключить интернет и повторить запрос — тогда придёт **«Не удалось получить ответ. Попробуйте ещё раз.»**, тоже без деталей исключения.

## Обработка ошибок

Все ошибки API в `llm.py` переводятся в готовые фразы для пользователя и не пробиваются в интерфейс сырым исключением:

- 4xx (доступ/настройка) → «Не настроен доступ к сервису.»
- 5xx (сервис недоступен) → «Сервис временно недоступен. Попробуйте позже.»
- таймаут/сеть → «Не удалось получить ответ. Попробуйте ещё раз.»
- пустой/битый ответ модели → «Пустой ответ модели. Попробуйте переформулировать вопрос.»

На 5xx и таймаут допускается один повтор запроса, на 4xx повторов нет.
